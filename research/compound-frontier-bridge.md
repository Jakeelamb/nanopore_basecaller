## Producer and completion chain

The `transform` command exclusively creates a new directory, writes its attempt, decisions, consistency and provenance, then writes and syncs completion last. Successful stdout contains exactly one completion pin. Python runs the native command under the shared host lock and GNU time, retaining command JSON, launch JSON, cwd, UTC clocks, exit status, stdout, stderr and time. Its `finish.json` describes the actual executed command and pins the raw recorder files.

The separate `admit` command binds that successful receipt to the exact transform argv, manifest, output directory, executable and compiled closure. It compares retained raw stdout with the transform completion pin, verifies the output seals, and independently rereads source/transformed decisions to check preservation. A successful unrelated command cannot serve as the producer.

The new `graph-frontier-cohort/1` keeps the original `pins.parents`, `pins.native_sam`, `pins.windows` and `pins.graph_walks`. It replaces `pins.decisions`, sets the bridge transform receipt as `producer_receipt`, removes a nested original receipt if present, and sets `historical_sams` to `{}`. The unchanged generic emitter runs inside this actual admission process. `bridge-admission.json` binds its cohort, finite protocol, decisions, rule consistency and emitter completion. Package `complete.json` is written last. The outer admission recorder separately binds package completion to the successful admission process.

The old generic emitter's `parity.json` is interpreted only as expanded-H policy consistency. Its names do not establish original-H decisions or complete-parent historical SAM equivalence. Admission metadata explicitly denies that equivalence.
